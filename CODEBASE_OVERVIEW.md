## 1. Project at a Glance

`green-mango-core` is a **single-page marketing site** for the Mango Stack AI brand. It renders entirely on the server via TanStack Start (SSR on Cloudflare Workers) and hydrates client-side with React 19. The UI is a dark-mode landing page with animated sections, glassmorphism cards, and a Radix UI / shadcn component library.

There is **no backend API, no authentication, and no database** — all content is driven by a static CMS mock file (`src/lib/cms-data.ts`) with a clear migration path to Sanity.

## 4. Entry Points & Bootstrapping

### `src/server.ts` — Cloudflare Worker Entry
- The **outermost HTTP handler** (pointed to by `wrangler.jsonc`).
- Lazily imports the TanStack Start server entry (`@tanstack/react-start/server-entry`).
- Intercepts h3's swallowed SSR errors (JSON `{unhandled:true, message:"HTTPError"}`) and replaces them with a branded HTML 500 page.
- Uses `error-capture.ts` to recover the real Error stack before h3 drops it.

### `src/start.ts` — TanStack Start Instance
- Creates the `startInstance` with a global server-side error middleware.
- The middleware re-throws known HTTP errors and returns `renderErrorPage()` for anything else.

### `src/router.tsx` — Client Router Factory
- Constructs a `TanStack Router` with:
  - The auto-generated `routeTree`
  - A `QueryClient` passed via router context (so any route can use React Query)
  - `scrollRestoration: true`

## 5. Routing Layer

TanStack Router uses **file-based routing**. The route tree is auto-generated into `routeTree.gen.ts`.

```
__root  (src/routes/__root.tsx)
  └── /  (src/routes/index.tsx)
```

### `__root.tsx`
- Defines the HTML `<html>/<head>/<body>` shell via `shellComponent: RootShell`.
- Injects `styles.css` as a stylesheet link.
- Sets default SEO meta tags (overridden per-route).
- Wraps the route `<Outlet>` in `<QueryClientProvider>`.
- Registers `notFoundComponent` (custom 404) and `errorComponent` (custom error boundary).

### `routes/index.tsx`
- The only application route (`/`).
- Overrides head meta with Mango Stack AI–specific title and OG tags.
- Renders the landing page by composing all section components in order:
  `Navbar → Hero → LogoMarquee → Departments → FeatureSplit → Testimonials → CTA → Footer`

## 6. Component Architecture

### Landing Sections (`src/components/landing/`)

All section components follow the same pattern:
- Import data from `@/lib/cms-data` (single source of truth).
- Use `framer-motion` (`motion.*`) for scroll-triggered entrance animations (`whileInView`, `initial/animate`).
- Apply custom CSS utilities from `styles.css` (`.glass`, `.hover-glow`, `.text-gradient`, `.grid-bg`).

| Component | Section ID | Key Features |
|---|---|---|
| `Navbar` | sticky header | Dropdown mega-menu (desktop), animated slide-down mobile menu, glassmorphism |
| `Hero` | — | Framer Motion staggered entrance, gradient headline, dual CTA buttons, decorative mango images |
| `LogoMarquee` | — | CSS `marquee` animation, logo loop duplication, fade-edge gradient masks |
| `Departments` | `#solutions` | 4-column grid, mouse-tracking radial glow hover effect (`--mx`/`--my` CSS vars) |
| `FeatureSplit` | `#platform` | 2-col layout: feature checklist left, mock browser window + dashboard screenshot right |
| `Testimonials` | — | 3-col grid, same mouse-tracking hover effect as Departments |
| `CTA` | `#demo` | Full-width rounded card with grid-bg overlay + hero gradient |
| `Footer` (in CTA.tsx) | — | Minimal: logo + copyright |

### UI Primitives (`src/components/ui/`)
Full shadcn/ui component library — 46 components covering every Radix UI primitive. These are **pre-built and available** but currently unused by landing page sections (landing uses raw HTML elements with Tailwind for tighter design control). Available for future dashboard/app pages.

### Hooks (`src/hooks/`)
- `use-mobile.tsx` — Returns `boolean` based on a `768px` media query breakpoint.

## 9. Server & Error Handling

The project has a two-layer error handling system designed around Cloudflare Workers + TanStack Start:

```
Request
  └── server.ts (Cloudflare fetch handler)
        ├── try/catch → brandedErrorResponse() on hard throw
        └── normalizeCatastrophicSsrResponse()
              └── Detects h3's swallowed 500 JSON body
                    └── consumeLastCapturedError() (from error-capture.ts)
                          └── Returns branded HTML error page

start.ts middleware (per-request)
  └── Re-throws known HTTP errors (statusCode field)
  └── Returns renderErrorPage() HTML for all others
```

- `error-capture.ts`: Registers `error` and `unhandledrejection` global listeners. Stores the last error with a 5-second TTL so `server.ts` can retrieve it after h3 drops the original throw.
- `error-page.ts`: Returns a self-contained HTML string (no React, no Tailwind) — safe to send as a response before the app bundle loads.

## 10. Build & Deploy Config

### `vite.config.ts`
Extends `@lovable.dev/vite-tanstack-config` which bundles: TanStack Start, Vite React, Tailwind CSS, TypeScript paths, Cloudflare plugin, component tagger (dev), error logger, and `@` alias. Custom config only redirects the server entry to `src/server.ts`.

> ⚠️ Do **not** manually add `tanstackStart`, `viteReact`, `tailwindcss`, `tsConfigPaths`, or `cloudflare` plugins — they're already included by the base config.

### `wrangler.jsonc`
```jsonc
{
  "name": "tanstack-start-app",
  "compatibility_date": "2025-09-24",
  "compatibility_flags": ["nodejs_compat"],
  "main": "src/server.ts"
}
```
Deploys to Cloudflare Workers. `nodejs_compat` flag enables Node.js APIs in the Worker runtime.

## 11. Key Conventions

1. **Path alias**: `@/` maps to `src/` — use for all internal imports.
2. **Content changes**: Edit `src/lib/cms-data.ts` — never hardcode strings in components.
3. **New routes**: Create `src/routes/my-page.tsx` — TanStack Router auto-generates the route tree on next build/dev start. Do not edit `routeTree.gen.ts`.
4. **New UI components**: Follow the shadcn pattern — add to `src/components/ui/`, consume in feature components.
5. **Animations**: Use `framer-motion` with `whileInView` + `viewport={{ once: true }}` for scroll animations. Keep `initial` / `animate` for hero above-the-fold elements.
6. **Mouse glow effect**: Components using `.hover-glow` must include the `handleMouseMove` event handler that sets `--mx` and `--my` CSS custom properties.
7. **No light mode**: The design token system is dark-only. Adding light mode requires duplicating all `oklch` tokens under a `@media (prefers-color-scheme: light)` or `.light` selector.
